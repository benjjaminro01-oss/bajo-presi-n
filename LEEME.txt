CONFIGURAR FIREBASE (una sola vez)
1. Firebase Console > proyecto bajo-presion-7e430 > Storage (menu Compilacion). Si dice "Comenzar", pulsalo: elige modo de produccion
   y una ubicacion. Ojo: Firebase puede exigir el plan Blaze (con pago por uso) para activar Storage; el uso normal de este sistema es minimo.
   El bucket debe llamarse bajo-presion-7e430.firebasestorage.app (el mismo del firebaseConfig).
2. Storage > pestana Reglas: reemplaza el contenido por el de firebase/storage.rules y pulsa Publicar.
3. No hace falta cambiar las reglas de la Realtime Database ni crear otro proyecto.

   (salida.js no cambio: OBS reproduce las URLs de Storage tal como ya reproducia las rutas anteriores.)

SI LA BARRA SE QUEDA EN 0 %
- Storage no responde. A los ~40 s el panel muestra el motivo. Causas tipicas: Storage sin activar (Firebase Console > Storage > Comenzar),
  reglas sin publicar, o un bloqueador de contenido/VPN que bloquea firebasestorage.googleapis.com. Safari: Desarrollo > Mostrar inspector web >
  Red, filtra "firebasestorage" y mira el codigo de estado de la peticion.

SI UNA GRAFICA NO SE REPRODUCE
- La salida avisa el motivo: en la lista de MEDIOS aparece una linea amarilla. Pulsa "Probar" en la fila: dice si el archivo se carga
  y si el navegador puede decodificarlo (codec, tamano 1920x1080).
- Exportar el MP4 desde After Effects: Composicion > Anadir a la cola de Adobe Media Encoder. Formato H.264,
  preajuste "Coincidir origen - Velocidad alta", 1920x1080, perfil High, 8 bits (4:2:0), audio AAC,
  y activar "Optimizar para transmision". No sirven ProRes, HEVC/H.265 ni un .mov renombrado a .mp4.
- Error "Firebase rechazo la operacion": las reglas de Storage no estan publicadas o no coinciden con firebase/storage.rules.
- Error "Storage no esta activado": falta el paso 1 de CONFIGURAR FIREBASE.

SEGURIDAD
- El firebaseConfig del panel (apiKey, projectId, storageBucket, appId) es informacion publica de cliente, no un secreto. No hay claves
  privadas ni de administracion en el codigo.
- Como el sistema no usa Firebase Auth, Storage queda con el mismo criterio que la Realtime Database: no hay inicio de sesion. Las reglas
  limitan ruta, tipo (video MP4/WebM, imagen PNG/WebP/JPG), tamano (100 MB) y prohiben sobrescribir. Lo que NO pueden hacer es verificar
  el codigo de sala, porque Storage no puede leer la Realtime Database. Si quieres cerrar mas el acceso, el siguiente paso seria activar
  Firebase Authentication anonima (o App Check) y exigir request.auth != null en las reglas.
